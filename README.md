# 荒島槍戰：交接說明

一個瀏覽器裡跑的第一人稱小隊槍戰遊戲，整個遊戲就是 `game.html` 這一個檔案（Three.js r128 從 cdnjs 載入，其餘 CSS / JS 都寫在檔案裡）。

## 本機執行

直接用瀏覽器打開 `game.html` 就能玩（需要網路載入 Three.js）。
如果瀏覽器擋了 file://，在這個資料夾裡執行：

```
node serve.js
```

然後打開 http://localhost:8765/game.html（`serve.js` 是只服務這個資料夾的小型靜態伺服器）。

## 玩法（五種）

| 玩法 | 人數 | 地圖 | 勝負 |
|---|---|---|---|
| 吃雞 · 百人 | 100 人（4 人一隊 × 25 隊） | 原地圖放大 2.2 倍（約 5 倍面積），例如荒島 784×784 公尺 | 最後一隊生存，縮圈約 17 分鐘 |
| 吃雞 · 快速 | 32 人（4 人一隊 × 8 隊） | 放大 1.7 倍 | 最後一隊生存，約 11 分鐘 |
| 團隊死鬥 | 兩隊，每隊 4 / 6 / 8 / 12 人 | 競技場、辦公大樓、豪宅、科技世界（縮小版） | 5 / 10 / 15 分鐘，比擊殺數 |
| 單挑 | 1 對 1 | 競技場、辦公大樓、豪宅（小型） | 先拿 10 殺 |
| 軍備競賽 | 2 或 4 隊，每隊 2 或 4 人 | 競技場、辦公大樓、大公園、科技世界 | 手槍→霰彈→步槍→狙擊→平底鍋，每把 5 殺升級 |
| 狙擊賽 | 兩隊，每隊 4 / 6 / 8 人 | 大公園、總統府、沙漠、荒島、競技場 | 全員只有狙擊槍，10 / 15 分鐘比擊殺 |

- **配槍**：除了吃雞（落地空手要撿）與軍備競賽（照階段給）以外，開局就給步槍、霰彈槍、狙擊槍、手槍四把，彈藥充足。狙擊賽只給狙擊槍。
- **選單流程**：開始遊戲 →（選玩法）→（選地圖、難度、人數、時間）→ 進入戰場。滑鼠靈敏度移到暫停選單。

## 開局設定## 開局設定

人數由玩法綁定，不用自己算總數；地圖池也依玩法篩選（例如單挑只給小地圖）。

## 目前功能

- **開局可選 7 張地圖**：荒島、豪宅、大公園、總統府、辦公大樓（5 層 + 頂樓）、沙漠、科技世界
- **開局可選人數**：你的隊友 0–5 人、敵方 1–7 隊、每隊 1–6 人（最多 48 人同場）
- **跳傘開局**：運輸機隨機航線飛越地圖，空白鍵跳機 → 自由落體（WASD 操控）→ 78 公尺自動開傘 → 落地開打。每個 AI 都有自己的落點，各小隊散落在不同區域
- **地面拾取**：落地時手無寸鐵，地圖各處散落槍械、彈藥箱、醫療包、護甲，走過去按 **F** 撿槍（醫療包等走過即拿）。AI 落地後也會自己跑去撿槍、撿彈藥，沒槍時會先閃避
- **彈藥有限**：每把槍有彈匣與備用彈（步槍 30/90、霰彈 7/28、狙擊 5/20、手槍 15/60），**R** 換彈，換彈有時間；AI 一樣會打空、會換彈。被擊倒的人會掉落自己的槍與補給
- 四把槍：步槍（連射）、霰彈槍、狙擊槍、手槍。**右鍵開鏡**：步槍／霰彈／手槍是可透視的紅點鏡（看得到鏡框、中間透空、紅點在正中），狙擊槍是全螢幕倍鏡（槍身隱藏）
- Q / E 左右探頭（碰到牆會自動縮回），C 蹲、Shift 衝刺、空白鍵跳
- 會縮小的藍色安全區（6 個階段），圈外扣血
- 死亡後觀戰隊友，Enter 直接結算
- 小地圖：青點 = 隊友、橘點 = 隊友發現的敵人、紅點 = 剛開槍的敵人

## 常改的地方（在 game.html 裡搜尋）

| 想改什麼 | 搜尋 |
|---|---|
| 難度（命中率、傷害、反應時間、視野） | `const DIFF=` |
| 預設地圖、預設人數 | `const SET=` |
| 地圖清單（大小、天空、光線、地面、亂數種子） | `const MAPS=` |
| 某張地圖的地形內容 | `mansionLayout` / `parkLayout` / `palaceLayout` / `officeLayout` / `desertLayout` / `techLayout` / `islandLayout` |
| 跳傘高度、落下速度、開傘高度 | `const drop=`、`updateDropPlayer`、`dropUpdate` |
| 隊伍衣服顏色、隊名 | `TEAM_CLOTH`、`TEAM_LABEL` |
| 隊友血量 / 命中加成 | `team===0?130:100`、`ch*=1.25` |
| 槍的傷害、射速、後座力、彈匣與換彈時間 | `const WEAPONS=` |
| 地上掉落多少槍 / 彈藥 | `function scatterLoot` |
| 紅點鏡外型、開鏡時槍的大小 | `function sight`、`vmFov`、各槍的 `adsZ` |
| 狙擊鏡畫面 | CSS 的 `#scope` |
| 第一人稱槍枝外型 | `function buildGun` |
| 士兵外型（頭盔、背包、護具） | `function botGeo` |
| 安全區時間與傷害 | `const PHASES=` |
| 探頭距離與角度 | `// lean (Q / E)`，以及 `placeCamera` 裡的 `-P.lean*.2` |

每張地圖都有固定亂數種子（`MAPS` 裡的 `seed`），所以同一張地圖每場長得一樣；改種子就會換一張同風格的新地圖。

## 地圖可走性（2026-11-21 大修）

先前很多樓梯爬不上去、頂樓進不去，原因有三個，都修好了：

1. **樓梯是實心的**：每一階從地板長上來，上一層的樓梯剛好壓住下一層樓梯的頭部空間。改成鏤空踏板（`stairs()` 只產生踏板厚度）。
2. **樓板開口被屋頂補回去**：總統府、科技世界的屋頂整片蓋過樓梯口。新增 `slabHoles()` 可一次挖多個洞，屋頂與每層樓板都用它。
3. **樓層高度對不上**：樓梯起點比地板高 0.35 公尺，第一階變成 0.73 公尺（上限是 0.46）爬不上去。所有樓層的「樓板上表面」與樓梯起訖點重新對齊。

另外：沙漠的採油塔樓梯本來朝反方向、土屋的樓梯會被其他物件壓到（已預留空間）、科技世界的空中廊道樓梯直接蓋在塔裡（改成自動找空的通道）。

`stairRuns` 會記錄每一段樓梯，稽核腳本會放一個探針從底部走到頂部；目前 **8 張地圖、72 段樓梯全部可走**。高處（二樓以上、屋頂）的物資點保證會刷出槍或彈藥。

## AI 尋路（2026-11-23）

AI 以前只會朝目標直線走，遇到建築就卡死。現在：

- 每次建圖後產生 **1.1 公尺一格的導航格網**（`navBuild()`，記錄可走性與地面高度，大地圖約 11–13 萬格、耗時 170–190 毫秒）
- **A\*** 尋路（`navPath()`，二元堆、不切角、不爬超過 0.46 公尺的落差、避開大落差），每幀最多 3 次、每次最多 7000 節點
- 直線走得通就不尋路（`navClear()` 每 0.8 公尺取樣），路徑會做「看得到就跳過中間點」的平滑
- **監看機制**：3.5 秒沒有前進就判定目標不可達——物資會被加入黑名單（屋頂上的槍不會再讓 AI 卡在樓下）、巡邏點會換、死鬥模式改成先往別處晃
- 交戰中貼著掩體拉槍時，撞到東西會立刻換邊

實測（120 秒、每隻 AI 平均貼牆動彈不得的時間）：荒島 9.2→2.4 秒、豪宅 6.2→0.7 秒、辦公大樓 5.0→2.2 秒。團隊死鬥在豪宅從「150 秒 0 殺」變成 31:21。

- **復活點**：每隊有三個固定出生點（`buildTeamSpawns()`），復活時選離敵人最遠的那個

## 技術備註

- 地圖是執行時產生的：`buildMap(id)` 會清掉 `worldRoot`、重建空間格子、跑該地圖的 `build()`、再 `mergeStatic()` 合併成每種材質一個 mesh。新增地形物件要在 `mergeStatic` 執行前加入
- 碰撞用 AABB + 8 公尺空間格子（`near()`），子彈與視線用射線對 AABB 檢測，不是對 mesh
- 士兵每個部位是「一顆合併過的頂點著色 mesh」（`partsGeo`），整個人只有 6 個 draw call；打擊判定另外用 3 個看不見的 hitbox（`material.visible=false`，仍可被射線命中）
- 渲染是線性工作流：`outputEncoding=sRGB` + ACES tone mapping，所有材質顏色都呼叫 `convertSRGBToLinear()`，改顏色時要沿用 `mat()` 這個函式，不要直接 new 材質
- AI 敵人的命中是機率制（`shootAt`），不是真的射線打中玩家
- 武器模型在獨立的 `vmScene` 第二次渲染，所以槍不會穿牆
- 開啟網址時加上 `#dev` 會掛上 `window.__dev`（`land()`、`landAll()`、`arm('rifle')`、`tpNearBot()`），方便測試；一般開啟不會有任何影響
- 玩法由 `MODES` 定義（`drop` / `zone` / `loot` / `respawn` / `size` / 勝利條件），`MODE.size` 會縮放地圖尺寸
- 復活流程：`reviveEntity()`（玩家與 AI 共用），出生點 `spawnPointFor()` 會挑離敵人最遠的候選點
- AI 交戰時會在四種風格間切換（`combatMode`：定點射擊／左右拉槍／壓上／後撤），定點時會蹲下且命中率更高，移動中射擊命中率下降
- 跳傘期間（`state==='drop'`）AI 不會互相偵測，落地的人會立刻開始作戰；`dropDone()` 全部落地後才切到 `state='playing'`

## 2026-11-25 連線對戰（第一階段：本機／區域網路）
**怎麼玩**：在遊戲資料夾執行 `node server.js`，瀏覽器開 `http://localhost:8765`。
同一個網路的朋友改開伺服器啟動時印出的 `http://你的IP:8765`。
首頁 →「連線對戰」→ 房主按「建立房間」拿到 4 碼代碼，其他人輸入代碼加入（最多 12 人）。
房主選玩法與地圖後按「進入戰場」，全場一起開打。

**架構**：`server.js` 是零依賴的手寫 WebSocket 中繼（HTTP 靜態檔 + upgrade 握手 + 訊框解析），
只管房間與轉送，不跑任何遊戲邏輯。遊戲端採「房主權威 + 各自管血」：
- 房主模擬 AI、安全區、計分與比賽時間，每 55ms 廣播一份世界快照（bot 位置／朝向／血量／狀態旗標／移動速度、安全區 8 個數值、比分、剩餘時間）。
- 每位玩家每 50ms 廣播自己的位置、朝向、速度與狀態旗標。
- 開槍者做命中判定，再把傷害送給對方；打 AI 送給房主，打玩家送給那個玩家本人，各自結算自己的血。延遲低、不會有「我明明打到了」的落差。
- 擊殺由死者回報給房主計分，房主再把比分放進快照。

**實作重點**：
- 遠端玩家與遠端 AI 都用現有的 Bot 模型當外殼（`net=true`），所以命中框、名牌、小隊 HUD、擊殺播報全部沿用；`netUpdate()` 只做插值（位置 12/s、朝向 10/s）與動畫，不跑 AI。
- 隊伍用「換位映射」：每個客戶端看到的自己永遠是 0 號隊，房主的 0 號隊與自己的隊伍對調，所以隊色、友軍判定、不打自己人全都對。
- 房主在開局前產生完整名單（每個位置是誰、名字、座標、哪一隊）一次廣播，所有人照名單生成，不靠亂數同步。
- 隊伍分配可選「同一隊（一起打 AI）」或「分開（玩家互打）」。
- 連線對戰中停用暫停與切換分頁自動暫停——世界不會為你停下來。
- 房主離線時伺服器會把房主交棒給最早進來的人；比賽中則直接結算本場。

**這一階段不支援**：吃雞（跳傘、空投、地上撿槍還沒同步），連線場次不會生成地上物資。
團隊死鬥、單挑、軍備競賽、狙擊賽都可以連線玩。

**已驗證**：建房／加入／房主旗標／名單同步、兩端隊伍映射正確、快照（位置、血量、死亡、比分、時間）一致、
遠端玩家插值跟隨、真實射擊路徑（raycast 打到遠端玩家命中框 → 傷害過網路 → 對方扣血 100→65）、
槍聲 3D 同步、單機模式不受影響（7 隻 AI、16 個物資、無 roster）。

## 2026-11-25（第二輪）連線修正、遊戲內設定、空氣牆、效能

## 2026-11-25 第三輪：連線吃雞、席位選擇、遠景與質感

**連線吃雞**。原本連線只能打復活類玩法，因為吃雞的世界不是由房主算出來的，而是每台電腦
各自生成：地上幾百件物資、運輸機航線、每隊的空投落點。兩邊生成不一樣就完全對不起來。

作法是**共用種子**而不是傳整張清單：房主開局時抽一個 32 位元種子放進 `start` 訊息，
`withSeed(seed, fn)` 在生成期間把世界生成用的亂數換成 mulberry32，物資、航線、落點全部一致。

途中踩到一個不好找的坑：一開始是直接覆寫 `Math.random`，結果兩台電腦的世界還是不一樣。
原因是 three.js 產生 uuid 時也會抽 `Math.random`，而材質有沒有被快取在每台電腦上不同，
抽號次數一差，後面整條亂數流就錯開了。改成生成程式走自己的 `R()`，不碰 `Math.random`。

生成以外的東西用訊息同步：
- `take{p}` —— 每件物資有固定編號（照生成順序），有人撿走就從所有人畫面移除。
- `pk{k,x,z,y,p}` —— 陣亡掉落這類途中才生成的物資，編號帶上玩家 id 避免撞號。
- `ad{x,z,i,o}` —— 空投由房主決定位置與內容再廣播，箱子裡三件東西的編號從空投編號推出來。
- 狀態旗標多了「在空中」和「正在扶人」兩個 bit，遠端玩家的降落傘和救援才會正確。
- 倒地救援只由自己那台電腦結算，別人的角色不代算，兩邊才不會打架。

**席位選擇**。原本只能選「同隊／分開」，現在選完玩法會多一個席位畫面：照實際編制畫出
每一隊的位子（例如 2 隊 × 8 人就是 16 個席位），點空位就坐進去，沒人坐的由 AI 補。
房主是席位的權威，有人離開會自動空出位子。吃雞固定全員同隊，所以只顯示一隊，
每隊人數會跟著房內人數長大。

**遠景與地面質感**：
- 每張地圖都有三層由遠而近的山稜，顏色事先混進霧色所以不吃霧（吃霧的話全部會被霧吃掉），
  愈遠愈淡；科技世界和辦公大樓改用方塊天際線。
- 地面撒大小不一的色斑、幾條蜿蜒的土路、草叢；草叢和遠景都不進陰影 pass。
- 地面平面 1800 → 4200 公尺（遠景山要站得住），貼圖重複次數同步放大，不然每格會被拉大兩倍。
- 實測：99 人吃雞每幀邏輯 p50 1.2ms、p99 6.9ms，沒有一幀超過 16ms。

**介面**：HUD 與選單改用毛玻璃面板、統一圓角與分層陰影，頂端數字加上顏色提示線，
血條護甲條加微光，按鈕改漸層並加上按壓回饋。房間畫面多了可直接複製的連結。


### 同日修正：地圖破圖

上一版的地景有兩個會把整張地圖毀掉的錯：

1. **遠景山稜用絕對公尺數決定大小**。高度 80–240 公尺、寬度最多是高度的 2.2 倍，
   而擺放半徑只跟地圖大小鬆鬆地綁著——在沙漠、荒島這種大地圖上就變成 400 公尺高、
   900 公尺寬的巨牆貼在場邊，整片天空和地面都被蓋掉，看起來就是一堆飛起來的大色塊。
   改成**尺寸一律由距離決定**：高度 = 距離的一到三成，水平半徑不超過距離的三成，
   而且硬性保證 `半徑 < 距離 − 地圖邊界 − 20`，山絕對不會伸進場內。
   另外圓錐幾何的半徑是 1（直徑 2），之前當成寬度用，實際上寬了一倍，一併修掉。
   加了測試掃過 8 張地圖 × 3 種尺寸共 24 組，檢查最近的山是否在地圖外、最遠的是否在相機遠裁切面內。

2. **地面色塊是一堆平貼的圓盤**。彼此共面會閃，而且 `CircleGeometry(1,9)` 是九邊形，
   半徑 26 公尺的那幾塊在腳邊會露出一條很明顯的直邊，看起來像地板破了一個洞。
   改成**一張有頂點顏色的地形網格**：顏色是連續漸層（大塊乾濕色斑 + 蜿蜒土路都畫進頂點色），
   沒有邊、沒有共面衝突，成本只有三萬個頂點。外圈那張大地面同時降到 −8 公分，不會和它打架。

順便把草叢改小：原本最高 1.65 公尺、最寬 0.88 公尺，立在地上像三角錐；
改成高 0.26–0.6 公尺的細葉片，顏色比地面深一點。
